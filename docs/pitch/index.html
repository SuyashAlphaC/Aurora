The Problem

When flood, cyclone, or earthquake strikes, coordinators cannot answer three life-critical questions fast enough.

1. Which shelters have room?

Occupancy is tracked by hand and radio. Families are sent to shelters that filled up 15 minutes ago.

2. Are shelters safe?

Air quality, heat, and water hazards go unmonitored while overcrowding makes conditions worse.

3. Is connectivity up?

Registration, medical records, and reunification depend on network links that fail silently.

Why manual coordination fails

  • Fragmented data — occupancy, environment, and network live in separate silos.
  • Human latency — phone trees add 10–20 minutes per decision.
  • Reactive ops — teams learn about crises after harm is already likely.
  • No single truth — field volunteers and EOC staff work from different snapshots.

Who We Serve

Disaster Response Coordinator

Primary user. Needs one live map, prioritized alerts, and trusted reroute recommendations in the EOC.

Shelter / Relief-Center Manager

On-the-ground operator. Needs automatic occupancy and environment reporting instead of manual headcounts.

Field Volunteer / First Responder

Guides evacuees. Needs reliable “go to Shelter D — room and safe air” instructions via Webex.

Evacuee (indirect)

Community member seeking safety. Benefits from faster placement in a non-overcrowded, safe shelter.

The Solution

Aurora is a Cisco-powered command center that unifies sensing, state, forecasting, engagement, and security in one pipeline.

Live ingestion

Continuous occupancy, environment (AQI, temp, water), and network health per shelter.

State engine

HEALTHY → WARNING → CRITICAL from transparent threshold rules.

Forecasting & reroute

Capacity prediction plus scored alternatives with human-readable reasons.

Action layer

Webex Adaptive Cards for coordinators; Duo MFA secures the console.

Golden-path demo scenario

  1. Surge hits Shelter B — occupancy and AQI climb via telemetry simulator.
  2. Forecasting service predicts capacity breach; state engine flips to CRITICAL.
  3. Webex bot posts an Adaptive Card to the coordinator space.
  4. Coordinator logs in via Duo MFA and accepts reroute to Shelter D.
  5. Dashboard map and alert feed update live over WebSocket.

Connect Meraki Dashboard API

What it does
Polls organization uplink status and maps each shelter to a Meraki network. Network degradation can trigger WARNING/CRITICAL states.
Why Meraki
Cloud-managed with a unified REST API — no on-prem controller required during infrastructure failure. Same fabric can host environmental sensors.
Wired in code
services/api/src/cisco/meraki.ts → poller → processTelemetry() → WebSocket broadcast.

Sense Sensors + telemetry simulator

What it does
Ingests occupancy, air quality, temperature, humidity, and water-leak signals per shelter.
Why Cisco sensing
Reuses shelter Wi‑Fi infrastructure — no separate IoT gateway to deploy in a crisis. Production path: Meraki MT/MV and Cisco Spaces.
Wired in code
POST /api/telemetry → state engine → SQLite → dashboard via /ws/live.

Observe ThousandEyes

What it does
End-to-end path visibility across networks Aurora does not own — critical when traffic crosses damaged ISP or satellite links.
Why ThousandEyes
Simple ping checks cannot localize where connectivity broke. ThousandEyes answers “is it down, where, and why?”
Wired in code
services/api/src/cisco/thousandeyes.ts — lists network tests; surfaced in /api/health. Optional for demo.

Engage Webex Bot + Adaptive Cards

What it does
Posts CRITICAL alerts to a coordinator space with Accept/Dismiss buttons. Meets responders where they already collaborate.
Why Webex
Free developer APIs, Adaptive Cards, webhooks — and the enterprise/government collaboration standard in Cisco’s Engage layer.
Wired in code
State engine → sendCriticalAlert() → Webex Messages API. Optional webhook: POST /api/webhooks/webex.

Secure Duo Auth API

What it does
MFA-gates the coordinator dashboard and protected API routes. Sensitive shelter data requires verified responder identity.
Why Duo
Real second factor on a free tier — proves the Secure layer for judges, composes with Webex identity story.
Wired in code
Dashboard login → /api/auth/login → Duo push/passcode → session token → Bearer on API + WebSocket.

Intelligence Forecasting & reroute service

What it does
Projects time-to-capacity and ranks alternate shelters by distance, spare capacity, environment, and network health — with reasons.
Why explainable
Emergency decisions must be auditable. Coordinators see “Shelter D: 40% full, air OK, uplink healthy” — not a black box.
Wired in code
API client → POST /ai/forecast and POST /ai/reroute on Python service (port 8001).
